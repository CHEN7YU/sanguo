# 三国志昭烈传：开发意图与协作交接

本文供项目成员、Codex 和 GitHub Copilot 共同阅读。维护日期：2026-10-11；代码基线：`e3302ee`。它记录产品意图与开发约束，不代表所有功能均已验收。

## 1. 我们在做什么

以《三国志英杰传》为基础制作现代化战棋重制游戏，名称为**三国志昭烈传**，开始界面出品文字以用户指定的 **InktoLife & Pandaking联合出品** 为目标。旧文案若仍存在，应统一检查，不能据旧 README 改回。

保留原作故事、人物关系、关卡分支和战棋框架，提高画面、动画、操作与跨设备体验。不是《曹操传》，也不是依三国历史印象另编一套关卡。用户明确批准的扩展玩法需要保留。

PC 优先，同时支持手机、平板浏览器横屏触控。目标包括 1080p、1440p、4K 与移动设备缩放。用户无需安装即可体验；浏览器不允许的有声自动播放、强制横屏或全屏需要优雅降级，不能承诺绕过平台限制。

## 4. 故事与关卡流程

- 从原文件确认战前、战中、战后对白及事件顺序；普通胜利、单挑胜利、分支选择不能混成同一段。
- **汜水关、广川/信都、巨鹿/清河和界桥的小人走位、刘备自由行动与 NPC 交谈必须保留。**虎牢关前按原作只演出大地图追击，不虚构营帐。
- 北海及以后默认使用“场景背景＋重绘头像＋对白”。需要自由交谈时，在背景上显示 NPC 选项；道具屋使用背景和菜单。简化表现，不删对白、选择、奖励、出征和整备。
- 普通对白任意键、点击、轻触推进，保留自动播放和整段跳过，不重新加入对白历史选项。自由行动时移动与交谈输入不能误触跳剧情。
- 选关默认从该关剧情开始；连续通关保留真实成长、装备、金钱、道具与路线。选关使用适合该关、能打过但不碾压的初始配置，不能全员一二级，也不能污染连续通关存档。
- 虎牢关之后保留路线选择，不能直接强制进入广川。原作要求的盟军按剧情随行，商店不提供“邀请盟军”选择。
- 跳过剧情也执行必要状态交接；重复读档或跳过不能重复发奖励。
- 后续关卡的背景、NPC 选项和文字须与前文人物关系、地图地点一致，禁止用几句旁白代替完整剧情。

## 5. 战斗规则：原作与明确扩展

原版移动、射程、兵种克制、策略学习等级、消耗、地形、士气、经验和奖励按审计落实。所有阵营使用相同的兵种/等级资格校验。不能给每个兵种统一塞三个技能，尤其不能让低级骑兵凭空有援助。

- 河流通过桥梁等合法通道跨越；悬崖、高山等障碍按对应地形和兵种限制。不能只凭画面“像山”一律禁止，也不能让单位任意翻过峭壁。
- 出生点、援军入口、桥头、目标建筑都要验证通路。背景地形与逻辑格子一致。
- AI 应能正常移动、物理攻击、使用合法策略并结束回合；不靠无条件施法拖长战斗。避免堵桥、反复横跳和盟军过强抢走关键目标。
- 恢复只按合法地形、道具或策略条件触发，不能每回合全体自动回血。当前豆的明确用户要求是恢复 200 兵力。
- 新加入武将同样能购买、装备和转交物品。战利品如长枪、连弩必须进入可查阅使用的库存。
- 击败某人、单挑胜利和关卡胜利分开判断。例如张飞与颜良单挑不等于击退张郃过关。
- 每名具名将领败退应有台词，优先原作，无原文才按人物创作并标明；所有单位有死亡/撤退表现。
- 我方行动后的待机提醒应清晰，不能误导新玩家直接结束全军回合；单位待机后仍能选择其他未行动单位。

以下为用户明确要求的自定义规则，不能以“原版没有”为由删除：

| 扩展 | 必须保留的意图 |
|---|---|
| 刘备辅助光环 | 身边友方受益，敌军绝不能受益；用户要求属性提高 10%，实际哪些字段生效须对照规则实现和面板。与关羽/张飞会合有“大哥我们合兵一处”对白，避免重复刷屏。 |
| 张飞「斗神」 | 永久被动，会心率提高 **10 个百分点**，属性面板可见，老存档也兼容。 |
| 关羽「千里行」 | 永久拥有的被动；移动越远，本次攻击增益越高，上限 10%。当前规则为每格 2%；增益不能跨行动无限累积，面板与预览说明清楚。 |
| 具名将领会心/格挡 | 概率配合属性显示；会心有发光蓄力，格挡有兵器动作。我方会心前有符合身份的台词。 |
| 三英战吕布 | 允许在原作触发基础上扩写精彩交锋，不能用张飞一次普通攻击替代三人剧情；扩写不得冒充原版台词。 |
| 每关成绩榜 | 时间计入评分，每关独立榜单；用户明确暂不区分连续通关和选关成绩。评分变更要说明，不能暗中改变历史成绩含义。 |

## 6. 美术与动画标准

人物身份来源的具体提取规则见 AGENTS.md。**人物 ID 不等于头像 ID**。每张头像必须有“人物编号→原作头像编号→原头像参考→重绘图”的来源链，不能再把曹操配成庞统。

- 头像：以原作造型、脸型、帽冠、胡须、服色重绘，成熟半写实古典战棋头肩像；禁止随意换成其他三国游戏人设。
- 战场小人：参照现有刘备、关羽、张飞，略 Q 版、轮廓清晰、紧凑英雄比例。头像风格和小人比例不是一回事。
- 每单位一个清楚的将领/兵种形象，不在身后挂一队小兵。骑兵要骑马；视觉换马不自动授权改变原作兵种数值。
- 武术家、贼兵、军乐队等有可辨识的专属轮廓和动作，不能全拿普通步兵或长矛兵顶替。
- 我方、盟友服饰区别于敌军红色，但脸和皮肤必须保持正常肤色；不能整图滤成青绿色。缺图不能只剩旗杆而仍宣称正常。
- 地图保留原版配色与经典战棋质感，提高细节；逻辑格子为方格，禁止把整张地图拉长压扁凑格子。水、桥、道路、树林、建筑与通行格一致。
- 行走需要真正的腿/马步动作；待机为呼吸、换脚、试弦等局部动作，不是整张图上下漂移。濒死表现虚弱或跪地，骑兵合理处理坐骑。
- 行走、攻击、受击、格挡、会心、濒死、死亡衔接时保持尺寸、脚底锚点、朝向和武器连续。闲置脸部可读，同时方向朝向敌人。
- 刀剑挥砍、枪矛刺击、弓箭射击分别制作。单挑双方面对对手，冲锋和兵器接触距离真实可见，不能隔空背身攻击。
- 所有动画资源压缩发布；高清母版留 `assets-master/`。不得为省体积删除以后重绘所需母版。

## 7. 声音、触控与存档

- 剧情先用原作相应音乐，战斗采用已经指定的曲目；不要擅自换音乐。音乐与音效独立音量，兵器、命中、脚步应听得清。
- 所有关卡骑兵移动有马蹄，步兵移动有脚步。避免切场后双 BGM 或重复播放实例。
- 手机/平板按钮不遮住人物；横屏时待机、设置等命令不能出屏。支持手动放大及地图拖动，拖地图不能拖走整个网页。
- 主菜单返回、视频完成/跳过、继续游戏均须恢复可操作界面，不能停在无按钮封面。
- 每个访问者的本地存档属于自己的浏览器环境；导入/导出必须清楚易用。不能宣称本地存储永不丢失或天然跨设备同步。
- 手动/自动存档应保存剧情进度、事件、分支、部队与道具；旧格式迁移先验证再写入，导入失败不能覆盖现有进度。
- 登录与个人云存档属于 TODO 中的后续工作，不等于已有排行榜服务自动具备此功能。


排行榜服务的安装/运行按其子目录说明单独处理；不要为了运行静态游戏盲目给整个仓库套新的打包框架。

## 9. 两人、两种 AI 的协作流程

共同仓库：`CHEN7YU/sanguo`。当前选择只保留一个长期主干 `main`，两位开发者直接在主干协作，不保留每人一条长期分支。

1. 开始任务前在群里写明目标和准备修改的文件，先确认另一人没有同时修改相同范围。`game.js`、`story-data.js`、同一关卡文件和同一套素材同一时间只由一人负责。
2. 开工前检查本地没有未提交改动，切到 `main`，执行 `git pull --ff-only origin main`。如果失败或出现冲突，先停止并查明原因，不能继续覆盖。
3. 小步修改并运行相关检查。完成后 Commit；Push 前再执行一次 `git pull --ff-only origin main`，确保期间没有新的远端提交。
4. 最后执行 `git push origin main`。如果被拒绝，说明朋友已经先推送，必须拉取并人工整合后重新测试；禁止 `--force`。
5. 高风险重构、预计多人同时开发、试验性功能或需要代码审阅时，仍可临时开短期分支和 PR，合并后立即删除；这不是长期树干。
6. 发布网页是单独动作，**Commit/Push 不等于网站已经更新**。发布记录对应提交、测试入口与验证结果。

用户明确说“push GitHub”“push github”或同义指令时，这是直接更新远端 `main` 的持续授权：先运行与改动相称的检查，把当前已完成工作 Commit，最后 Pull 检查远端进度并 Push `main`。不得因此新建功能分支或只推临时分支。若远端已产生冲突、检查失败、存在无法安全归属的混合改动，或者只有强推才能继续，应停止并报告具体原因；此授权不包含强推。

AI 不自动强推、丢弃未提交改动、覆盖他人提交、删除未合并工作或修改仓库权限。两人直推主干的前提是先分工；Git 无法防止双方同时修改同一行。

## 11. 资源与发布的已知风险

- 曾发生发布扫描只识别完整字符串，漏掉 `root + 文件名` 拼接引用，导致剧情立绘/小人在线缺失。清理资源不能只做简单文本搜索，须检查动态路径和所有关卡。
- 发布目录也要运行 `node tools/verify_release_assets.mjs "发布目录"`；北海剧情另有 `verify_beihai_story_portraits.mjs`。本地资源存在不代表公开网页已包含。
- `tools/sync-site-dist.ps1` 当前仍含原开发机的绝对发布目录。合作者不能直接照搬运行；先确认或参数化目标，不能写错目录。迁移打包流程属于待改进项。
- Cloudflare Workers 试玩使用根目录 `wrangler.jsonc` 与 `node tools/build-cloudflare.mjs`，仅发布生成的 `dist`，不得将仓库根目录作为资源目录。构建会检查缺失素材、LFS 指针和 25 MiB 单文件限制；配置见 README。旧 Sites 脚本不受影响。此配置不代表已发布或已完成大陆网络/设备验证，排行榜新域名授权、数据库迁移、微信登录及云存档仍需独立处理。
- 仓库、母版、Git 历史、发布包、玩家首次下载是不同体积指标，报告大小时明确口径。不要把整个开发目录上传网页。
- 普通关卡 3～6 MB、重点关卡不超过 15 MB 是用户提出的资源预算目标，并非现状承诺；共用资源单列。保持清晰度的压缩和按关加载需测量验证。
- 自动 WebP/AVIF/Opus 转换、通用包＋章节包、资源预算门禁的完整流水线仍应按 TODO 核实推进，不能因为已有 WebP 就宣称全部完成。
- 密钥、个人存档、原游戏安装包、缓存、发布临时包不应随功能提交；删除资源需先确认引用与可恢复的母版。
