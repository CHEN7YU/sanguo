## 剧情场景制作规则

- 汜水关、广川/信都、巨鹿/清河和界桥等前期章节保留或补齐剧情小人进场、走位与自由交谈，使战斗之间仍有角色扮演节奏；虎牢关前按原作只演出大地图追击，不额外虚构营帐。
- 北海及以后新关卡的剧情表现默认采用“每个场景一张高清重绘背景＋人物立绘＋对话框”的形式，按原作场景、人物、对白和事件顺序推进；若以后明确要求某关恢复自由行动，再针对该关制作。
- 原作允许选择人物交谈时，直接在当前背景图上显示清晰的人物选项；选择后进入该人物的立绘对话，结束后返回选项界面。
- 道具屋同样使用专用背景图和菜单选项，购买、出售、转交、整备和离开均在该界面完成，不制作人物在店内走动的流程。
- 背景、立绘、按钮和文字继续适配电脑、手机及平板横屏；选项必须支持鼠标、键盘和触屏。
- 这一规则只简化剧情操作表现，不删减原作对白、分支、奖励、整备、存档节点和剧情状态继承。

### 用户名与4位数字密码（功能分支）

游客点击“直接开始游戏”即可玩；需要跨设备存档时点击“账号登录 / 注册”，用用户名和4位数字密码注册，成功后直接登录。登录已有账号使用相同表单；新用户名不会自动注册，必须明确切到注册模式。

用户名为2—20个中文、英文字母、数字或下划线，去除首尾空格，英文字母不区分大小写。密码必须是**恰好4个 ASCII 数字**，允许 `0000`、`0123`，不得将其转换成数字丢掉开头的0。目前没有找回、重置或旧微信账号绑定功能，请记住账号并定期导出进度。不要使用银行卡或手机支付密码。

建立专用测试 D1，在 Wrangler 配置增加 `d1_databases` 项，字段为 `binding: AUTH_DB`、实际 `database_name`、实际 `database_id`、`migrations_dir: migrations`，另设 `AUTH_ORIGIN` 为完整 HTTPS 游戏源站（不含路径）。不得复用或覆盖原排行榜数据库。数据库 ID 不是密钥，可提交；密码 Pepper 必须使用 Secret，不能放源码、前端或聊天里。

预览与正式环境各有独立 D1 绑定；登录使用0001—0003迁移，本次后台统计新增 **0004**。`AUTH_PASSWORD_PEPPER` 只在新环境首次设置，至少32字符，建议64字符随机值；两站均已配置，后续部署必须保留各自现有 Pepper，不能照着首次部署步骤再次生成覆盖。直接换值会使现有密码无法登录，目前没有密钥轮换流程。

```text
npx wrangler d1 migrations apply sanguo-wechat-preview --remote --env preview
npx wrangler deploy --env preview
```

以上是独立预览环境更新命令，不能省略 `--env preview`。新环境须配置单独数据库并应用 **0001—0004** 全部迁移，首次通过 `wrangler secret put AUTH_PASSWORD_PEPPER` 设置对应环境的 Secret。不要重写已经执行的旧迁移；历史微信身份表留存但接口已移除，不把新用户名擅自关联到旧账号。未配置 D1、HTTPS 源站或 Pepper 时登录明确显示未配置，游客入口仍可使用。

Worker 仅在 `/api/*` 执行后端，其他文件由静态资源服务处理。注册/登录仅接受同源 POST JSON；密码先经服务器 Pepper HMAC，再用随机盐和 PBKDF2-SHA256（100000次）派生，D1 不存明文密码。七天 HttpOnly/Secure 会话 Cookie，D1 只存令牌 SHA-256 哈希；登录替换当前会话，每账号最多五个有效会话，退出撤销当前会话。

每用户名最多5次/15分钟尝试，每来源 IP 登录最多20次/15分钟，注册最多5次/小时；成功也计入窗口，不自动清零。限额使用 D1 原子计数，超限返回429与 Retry-After，不在日志里记录密码或原始 IP。过期桶随请求限量清理。**4位密码仅有一万种组合，限流与加密不能使它达到高强度账号安全标准**；不要存敏感资料，正式开放前仍需隐私/删除流程、滥用处理与真实 Worker CPU/数据库负载验收。

本机 Node.js 24 可运行 `node tools\verify_password_login.mjs` 和 `node tools\verify_cloud_saves.mjs`（内存 SQLite、客户端模拟，不访问真实账号）。`node server.mjs` 只提供静态试玩，不伪装账号服务。完整后端测试用 Wrangler 与独立 D1；本机 `.dev.vars`/`.dev.vars.preview` 已忽略提交，可保存仅用于本地的测试 Pepper，不能复用生产密钥。本机 Windows ARM64 的原生 Node 无法安装 workerd，可使用已校验官方 x64 Node 与 Wrangler 4.147.0。手机/平板真机、跨设备同步与负载需另行验收。

### 账号云存档（功能分支）

配置 `AUTH_DB` 后应用登录/存档的 **0001—0003** 迁移，启用统计还需 **0004**，同时设置 `AUTH_ORIGIN` 与 `AUTH_PASSWORD_PEPPER`；不要只建登录表就开放服务。`GET /api/saves` 读取整套进度，`PUT /api/saves` 以服务器会话确定归属、校验来源并按版本原子写入，`GET /api/saves/history` 读取历史。客户端传来的账号标识仅用于检测其他页面切换会话，不用于授权。

游戏等待身份及本机档读取完成后才初始化关卡。游客沿用原浏览器存档；账号的自动档、六个手动档、跨关继承、通关关卡列表、导入备份与待同步记录存入独立命名空间。登录后可通过“继续游戏”恢复最近档位，主线/选关标记、剧情及战后分支随档保留。音量等浏览器设置和原排行榜身份暂不随账号同步。

进度先保存本机，自动同步按一分钟合并，手动存档与“保存到云端”立即尝试。云存档弹窗默认只显示状态、最近进度、“保存到云端”和“返回游戏”；恢复旧档、转入游客进度、切换游客及故障恢复文件放入默认折叠的“更多选项”。仅发生冲突或选择旧档时显示两份进度和确认按钮；取消旧档恢复不会上传或改变当前进度。离线待同步记录保留在本机；恢复网络时重新检查会话，账号变化或失效不把旧进度写给新账号。网络响应丢失后重用原请求 ID，避免重复版本。关闭网页前仍应确认“进度已保存到云端”；突然关闭不保证最后一分钟已上传，清除浏览器数据会丢失未上传内容。

新账号不会自动继承游客档；只有确认云端和本机账号为空才允许点击迁入。版本冲突显示双方最近关卡、回合/剧情、主线/选关和时间，由玩家选择整套版本，不按时间擅自覆盖。被替换版本留作本机导入备份，可用标题的“撤销上次导入”恢复；也可选择“导出故障恢复文件”保留账号本机原始记录作人工恢复备份，此原始文件不是普通导入格式。历史恢复需再次确认，并作为新云版本保存。

单档上限 **100 KiB**，账号当前进度包上限 **350 KiB**；最多保留三个旧版本，当前包和历史的 JSON 数据总量不超过 **500 KiB**，超出时从最旧历史开始淘汰。数据库表、索引、账号和会话另占空间，仍需监控 D1 总容量与读写额度；不承诺 1000 人并发或免费额度下无限同步。大档上传失败仍保留本机，不伪装同步成功。

同浏览器同账号使用 Web Locks 保持一个写入页面；第二页面只读并提示关闭另一页面后刷新，避免本机相互覆盖。不支持 Web Locks 的旧浏览器需更新或使用游客模式。云端不同设备的并发靠版本冲突处理。当前是技术原型，正式开放前仍需限流、隐私/账号删除流程、故障演练与真实网络负载测试。

### 后台访问与登录统计（不在游戏前台显示）

按用户确认的口径，以**北京时间 UTC+8 的自然日**统计，dev/prod 分库存储；后台查询需要 Cloudflare 管理员权限，不新增公开读接口或前台计数器。

| 指标 | 口径 |
|---|---|
| 访问次数 | 页面可见且统计脚本成功上报一次计一次；刷新、重新打开计新访问；同一次上报的重试不重复计数 |
| 每日独立访客 | 浏览器随机标识按日去重；不是实际人数，跨浏览器、无痕模式或清理浏览器数据会增加标识 |
| 成功登录次数 | 服务端实际创建会话时计数，包括注册后的自动登录；失败登录、读取会话不计 |
| 每日登录账号数 | 同一账号每天只计一次；总体独立去重，不把设备分组人数相加 |
| 设备 | 根据 User-Agent 粗分电脑、手机、平板、其他；不存完整 UA，桌面模式等情况可能误分类 |
| 当前注册账号数 | 查询当前密码账号表；与历史成功登录次数是不同指标 |

`analytics.js` 仅在后端明确启用统计时设置 `zhaolie-visitor-v1` 随机本机标识，上报不附带登录 Cookie、不发送账号/存档内容。服务端仅持久化按日 HMAC 去重摘要和设备类别，不保存原始 IP、完整 UA、原始浏览器标识或用于统计的原始账号 ID；IP只在请求内生成限流桶摘要。每 IP 每分钟120次、每浏览器每分钟30次上报上限；限流、离线、存储受限、脚本被阻止等会导致漏计，不是审计或反作弊系统。未单独识别机器人，开发和验收访问也会计入。

启用条件为 `ANALYTICS_ENABLED="true"`、D1、HTTPS源站及现有 Pepper 均已配置。成功登录计数与会话创建在同一个 D1 事务中，写入失败明确报服务不可用，不伪装登录成功。去重事件及摘要保留最近7个统计日，每日北京时间00:15定时清理过期记录与限流桶；每日汇总长期保留。不同日期的独立访客数不能直接相加当成跨日实际人数。上线前的访问/登录历史无法补算。

管理员读取总访问、总登录、今日去重、近7天和设备分布的 SQL 在 `tools/analytics-report.sql`。本机 Windows 查询必须先把 SQL 压成一行；多行 `--command` 可能只执行第一条，而远程 `--file` 是文件导入模式，仅返回执行摘要，不是报告结果：

```powershell
$sql = (Get-Content tools\analytics-report.sql -Raw) -replace '\s+', ' '
npx wrangler d1 execute sanguo-prod --remote --command "$sql" --json
npx wrangler d1 execute sanguo-wechat-preview --remote --env preview --command "$sql" --json
```

## 操作

- 左键选择我军，点击蓝色格移动，点击红色范围内敌军攻击。
- 敌军已经相邻时，可点击右侧“攻击”原地出手；鼠标移到目标上会显示伤害与士气损失区间、溃退风险、命中、会心、格挡、反击概率、预计反击伤害、兵种克制和地形防御。
- 悬停可移动格会显示实际寻路路线以及逐格累计消耗。“敌军危险区”显示敌军移动后的物理攻击范围，并纳入当前站位可施展的火攻与牵制范围。
- 每名主要武将使用独立五帧攻击动作：刘备双剑连斩、关羽关刀挥砍、张飞与公孙瓒长矛直刺、陶谦与华雄刀剑攻击；普通刀兵、矛兵和弓兵也有对应动作。所有阵营和兵种在受到致命攻击时都会倒地、扬尘并淡出，旌旗同步消失；关羽、张飞、公孙瓒和华雄另有各自五帧马匹失衡、跪倒、人与马落地动作，不再把整张骑兵图直接旋转压扁。
- 第一关全部12个单位都已接入四方向、每方向四帧的专门行走图。刘备、关羽、张飞、公孙瓒、陶谦和华雄使用各自重绘素材，其他武官、弓兵与普通步兵使用对应兵种素材；行进时按真实路径换向，并逐帧校准脚底和人物尺寸，不再用整张人物图旋转、漂移或压缩来冒充走路。
- 近战攻击会根据目标所在格自动判断东、西、南、北方向：东西方向使用武器专属五帧动作，南北方向使用对应朝向的逐帧姿态配合突进和武器轨迹，不会在纵向交战时突然转成侧脸。演出包含蓄力、突进、武器命中、停顿、震屏和伤害数字；受击单位连续经历闪白、压缩扭身、击退和回弹，弓兵保留清晰的侧向拉弦动作，箭矢会按实际目标方向飞行。
- 策略菜单按原版兵种与等级学习表显示：短兵6级才学会焦热，轻骑兵8级才学会牵制，援助只属于具备恢复策略的辅助兵种。第一关全部参战单位等级不足，因此没有固有策略；火攻必须使用焦热书，恢复必须使用豆，骑兵不会凭空出现援助指令。
- 自动阵营同样受策略学习表约束，并且本回合能移动后物理攻击时始终优先交战；策略另有回合冷却和重伤恢复门槛，避免敌军连续施法而很少使用兵器攻击。
- 开战前可在道具屋购买豆、酒和焦热书，并指定刘备、关羽或张飞携带；消耗品、青龙偃月刀和蛇矛都能逐件转交给另一名我军武将。每名武将的宝物和道具合计最多8件，攻击加成随宝物持有人实时重算；“恢复初始军需与宝物”会恢复进入当前关卡时的军资金、道具和宝物归属，不会抹掉上一关的继承状态。公孙瓒、陶谦按剧情固定加入，无需在道具屋重复邀请。战斗中“道具”指令按携带者独立计数，可用豆恢复200兵力、麦恢复400兵力、酒恢复50士气；焦热书按原版规则必中，伤害由基础威力200减去目标策略能力后随机浮动，树林再增加25%，并给予攻击经验。村庄和鹿砦在对应阵营回合开始时恢复兵力与士气。状态栏实时显示士气，低于30时用红色提示混乱风险。宝物栏会显示青龙偃月刀攻击+12%、蛇矛攻击+10%等已计入数值的原版效果。
- 武将攻击和击破敌军会获得经验，击破强敌与主将奖励更多；经验达到100后升级并保留溢出经验，同时提升兵力上限、攻击和防御。右侧武将信息与出阵列表会实时显示等级和经验。
- 战场单位头顶在兵力条下方显示士气条，出阵列表也显示每人的士气数值；低于30时统一转为红色警示。
- 右键取消行动；也可使用右侧的待机、取消和结束回合。方向键移动键盘光标，Enter确认，A攻击、S策略、W待机、D危险区、Esc取消、空格结束回合。
- 鼠标滚轮缩放地图，按住中键拖动画面；触控板支持双指平移与捏合缩放。
- 设置里可开启“重复战斗动画自动加速”：同类攻击第一次完整播放，后续自动提速，关键会心、格挡与死亡表现仍会保留。
- 右上角设置可以调整0.75×—2×动画速度、独立音效音量、界面比例以及全屏；BGM音量保持独立控制。
